# Dify 3C 数码电商智能客服系统搭建指南

> **适用场景**：3C 数码电商（手机/电脑/配件），50 份产品画册 + 50 份客服话术，本地 Docker 部署
> **目标**：搭建一套可运营、可优化的 AI 智能客服，记录测试问题并达成召回率与客户满意度指标

***

## 一、成本与国内可访问性说明（重点！提前看）

| 组件                          | 说明                                         |
| --------------------------- | ------------------------------------------ |

| 模型                      | 问题            |

## 二、环境准备

### 2.1 硬件要求

| 配置  | 最低                    | 推荐                    |
| --- | --------------------- | --------------------- |
| CPU | 4 核                   | 8 核+                  |
| 内存  | 8GB                   | 16GB+（跑本地嵌入模型建议 32GB） |
| 硬盘  | 50GB                  | 100GB SSD             |
| 系统  | Windows 10/11 / Linux | Ubuntu 22.04 LTS      |

### 2.2 软件安装（Windows）

#### 步骤 1：安装 Docker Desktop

1. 下载 Docker Desktop：<https://www.docker.com/products/docker-desktop/>
2. 安装时勾选 "Use WSL 2 instead of Hyper-V"
3. 安装完成后重启，确保 Docker 引擎正常运行

#### 步骤 2：安装 Ollama（用于本地嵌入模型）

1. 下载 Ollama：<https://ollama.com/download>
2. 安装后打开终端，拉取嵌入模型：

```bash
ollama pull bge-m3
ollama pull bge-reranker
```

1. 验证安装：

```bash
ollama list
```

应能看到 bge-m3 和 bge-reranker。

### 2.3 部署 Dify

```bash
# 1. 克隆 Dify 仓库
git clone https://github.com/langgenius/dify.git
cd dify/docker

# 2. 复制环境变量配置
cp .env.example .env

# 3. 修改 .env 中关键配置（见下方说明）

# 4. 启动服务
docker compose up -d

# 5. 等待所有容器启动（约 2-3 分钟）
docker compose ps
```

**`.env`** **关键修改项**：

```
# 修改为你的机器 IP（WSL2 内用 host.docker.internal）
DIFY_BIND_ADDRESS=0.0.0.0

# 管理员账号
INIT_PASSWORD=你的密码
```

启动后访问：`http://localhost` （默认端口 80）

## 三、模型配置

### 3.1 配置 Ollama 嵌入模型

进入 Dify 后台 → 设置 → 模型供应商 → Ollama → 添加模型：

| 配置项      | 值                                   |
| -------- | ----------------------------------- |
| Base URL | `http://host.docker.internal:11434` |
| 模型类型     | Embedding                           |
| 模型名称     | `bge-m3`                            |

> ⚠️ 注意：如果 Dify 和 Ollama 在同一台 Windows 机器上，用 `host.docker.internal`；如果在不同机器，用 Ollama 服务器的实际 IP。

### 3.2 配置 DeepSeek 对话模型

设置 → 模型供应商 → OpenAI 兼容（自定义）：

| 配置项          | 值                             |
| ------------ | ----------------------------- |
| API Endpoint | `https://api.deepseek.com/v1` |
| API Key      | 从 platform.deepseek.com 获取    |
| 模型名称         | `deepseek-chat`               |
| 上下文长度        | 128000                        |

### 3.3 设置默认模型

设置 → 模型供应商 → 系统模型设置：

- 对话模型：deepseek-chat

- 嵌入模型：bge-m3

- 重排模型：bge-reranker（如果配置了）

## 四、知识库搭建

### 4.1 数据准备

#### 产品画册预处理（50 份，涵盖手机/电脑/配件）

- 每份画册对应一个产品型号（如 iPhone 16 Pro、小米15、联想小新Pro16等）

- 格式：优先 PDF（文本型），扫描件需先 OCR

- 单文件不超过 15MB，超大文件手动分割

- 去除页眉页脚、水印、目录等无关内容

- 建议统一转为 Markdown 格式，按以下结构整理：

  ```markdown
  ## 产品名称：iPhone 16 Pro
  ### 基本参数
  - 处理器：A18 Pro
  - 屏幕：6.3英寸 OLED
  - 存储：128G/256G/512G/1T
  ### 价格
  - 128G：7999元
  - 256G：8999元
  ### 卖点
  - 钛金属边框
  - 5倍光学变焦
  ```

- **关键**：参数、价格、规格等数字信息不要被分段切断

#### 客服话术预处理（50 份，涵盖常见咨询场景）

- 整理为问答对格式（Q\&A），每份包含一个主题的多个问答

- 覆盖以下主题：

  - 发货时效（下单后多久发货、发什么快递）

  - 退换货政策（7天无理由、15天质量问题退货）

  - 保修服务（1年质保、碎屏险、延保）

  - 支付方式（花呗、信用卡、分期免息）

  - 以旧换新（评估流程、补贴金额）

  - 安装/使用指导（新机激活、数据迁移）

- 去重：删除重复或内容高度相似的话术

- 分类标注：按意图分类（商品咨询 / 售后 / 物流 / 支付 / 投诉）

### 4.2 创建知识库

建议按内容类型**拆分多个知识库**，不要混在一起：

| 知识库名称     | 内容                | 用途                |
| --------- | ----------------- | ----------------- |
| `3C产品参数库` | 50份产品画册（手机/电脑/配件） | 回答型号、参数、规格、价格     |
| `售后政策库`   | 退换货、保修、碎屏险政策      | 回答售后相关问题          |
| `客服话术库`   | 50份标准Q\&A话术       | 匹配物流、支付、以旧换新等常见问题 |

> 💡 **拆分建议**：3C 产品参数结构化强，单独建库便于精确召回；售后政策和话术可按需合并或拆分。

### 4.3 分段策略（核心！影响召回率）

上传文档时，选择 **自定义分段**，配置如下：

| 参数     | 推荐值              | 说明                   |
| ------ | ---------------- | -------------------- |
| 分段标识符  | `\n###` 或 `\n##` | 按标题层级拆分              |
| 分段最大长度 | **512 tokens**   | 兼顾召回精度与上下文完整性        |
| 分段重叠长度 | **64 tokens**    | 10-25% 分段长度，避免边界信息丢失 |

### 4.4 检索配置

知识库设置 → 检索设置：

| 配置项  | 推荐值          | 说明                 |
| ---- | ------------ | ------------------ |
| 检索方式 | **混合检索**     | 向量 + 全文检索，兼顾语义和关键词 |
| TopK | **3**        | 初始值，后续根据测试调整       |
| 重排模型 | bge-reranker | 开启后召回准确率提升 20-40%  |
| 重排数量 | **5**        | 先召回 5 条再重排取 Top3   |

### 4.5 召回测试（上线前必做）

知识库 → 召回测试 → 输入关键词验证：

- 测试 10-20 个典型用户问题

- 检查返回的片段是否包含正确答案

- 如召回不准，先调分段和 TopK，再考虑换嵌入模型

## 五、Chatflow 工作流搭建

### 5.1 创建应用

Dify 工作室 → 创建应用 → 选择 **Chatflow**（不是聊天助手）

### 5.2 节点编排

```
开始 → 意图分类 → [分支路由]
                    ├─ 商品咨询 → 知识库检索(产品库) → 答案生成 → 结束
                    ├─ 售后问题 → 知识库检索(售后库) → 答案生成 → 结束
                    ├─ 常见问题 → 知识库检索(话术库) → 答案生成 → 结束
                    ├─ 投诉/不满 → 转人工 Webhook → 结束
                    └─ 无关问题 → 固定回复引导 → 结束
```

### 5.3 意图分类节点（LLM）

**System Prompt**：

```
你是3C数码电商客服意图分类器。将用户问题归类为以下意图之一，只输出意图名称：
- product_query：商品咨询（型号、参数、规格、价格、库存、对比）
- after_sales：售后问题（退换货、保修、碎屏险、维修）
- logistics：物流配送（发货时间、快递、运费）
- payment：支付优惠（花呗、分期、优惠券、以旧换新）
- complaint：投诉/不满
- unrelated：无关问题

示例：
用户：iPhone 16 Pro 有几个存储版本？ → product_query
用户：这款手机支持5倍变焦吗？ → product_query
用户：小米15和荣耀Magic7哪个好？ → product_query
用户：买的手机屏幕碎了能退吗？ → after_sales
用户：保修期多久？ → after_sales
用户：什么时候发货？ → logistics
用户：支持花呗分期吗？ → payment
用户：以旧换新能补多少？ → payment
用户：什么垃圾客服！ → complaint
用户：今天天气怎么样？ → unrelated
```

**模型**：deepseek-chat，temperature=0

### 5.4 知识库检索节点

- 选择对应知识库

- 检索配置复用 4.4 的设置

- 输出变量：`context`（检索到的片段）

### 5.5 答案生成节点（LLM）

**System Prompt**：

```
你是专业的3C数码电商客服。请根据以下知识库内容回答用户问题。
要求：
1. 只基于提供的知识库内容回答，不要编造信息
2. 如果知识库中没有相关信息，回复"抱歉，这个问题我暂时无法回答，已为您转接人工客服"
3. 语气友好、专业，回答简洁明了
4. 涉及具体数字（价格、存储容量、屏幕尺寸、电池毫安时、保修天数）时，必须准确引用，不能四舍五入或近似
5. 如果用户问产品对比，基于知识库中的参数客观对比，不要主观评价

知识库内容：
{{context}}
```

**参数**：

- temperature：0.2（低随机性，确保准确）

- max\_tokens：512

### 5.6 转人工节点

条件：`intent == complaint` 或连续两轮回答中包含"无法回答"

通过 Webhook 将对话历史推送到人工客服系统（如企业微信、钉钉、工单系统）。

## 六、测试与上线

### 6.1 测试清单（详见《测试问题与解决办法》文档）

- [ ] 意图分类准确率测试（50+ 样例，覆盖6类意图）

- [ ] 知识库召回率测试（30+ 典型问题，含参数/价格/对比类）

- [ ] 答案准确性人工评估（重点检查数字准确性）

- [ ] 多轮对话连贯性测试（如先问参数再问价格）

- [ ] 转人工触发测试（投诉/连续无法回答）

- [ ] 异常输入测试（乱码、超长文本、敏感词）

### 6.2 部署方式

- **测试**：Dify 内置预览界面

- **正式**：通过 Dify API 接入现有客服系统 / 网站 / 小程序

API 调用示例：

```python
import requests

API_KEY = "你的 Dify App API Key"
BASE_URL = "http://localhost/v1"

resp = requests.post(
    f"{BASE_URL}/chat-messages",
    headers={"Authorization": f"Bearer {API_KEY}"},
    json={
        "inputs": {},
        "query": "这款产品支持7天无理由退货吗？",
        "user": "user_001",
        "response_mode": "blocking",
        "conversation_id": ""
    }
)
print(resp.json()["answer"])
```
